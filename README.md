# 139OpenList

把**移动云盘（139）上的 CAS 占位文件**，变成一个可以在 **Cloudflare Workers** 上运行的只读播放网关。
挂到网易爆米花 / Infuse / VidHub 的 WebDAV 里，即可直接点播。

> 本项目为**原创实现**，专注一件事：**让 CAS 文件能播**。不含文件搬运、上传、转存等能力。

---

## 它解决了什么问题

移动云盘的空间靠"**秒传**"省下来的——视频文件上传后，本地只留一个几 KB 的
`.cas` 占位文件，里面记录着真实文件的名字、大小和哈希。

好处是省空间，坏处是**播放器不认识 `.cas`**，直接播是播不了的。

139OpenList 做的事，就是站在中间当翻译：

```
播放器请求 movie.mp4
      ↓
139OpenList 读到 movie.mp4.cas → base64 解码 → 拿到 SHA256
      ↓
拿着 SHA256 向移动云盘发起「秒传」，云端凭空"恢复"出真实文件
      ↓
取真实文件的下载直链 → 302 给播放器
      ↓
播放结束 → 自动清理临时副本
```

**关键点：全程零字节传输。** 恢复真实文件靠的是哈希匹配，不需要上传任何数据。
这正是它能跑在 Cloudflare Workers 上的原因——Serverless 没有长时间上传能力，
但发一个 API 请求完全没问题。

---

## 为什么能在 CF 上跑，而别的方案不行

| 依赖项 | 传统做法 | 139OpenList（本项目） |
|---|---|---|
| 恢复真实文件 | 靠上传接口传送字节 ❌ | 靠 **SHA256 秒传**，纯 API 调用 ✅ |
| 内存占用 | 需缓冲整个文件 ❌ | 只读几 KB 的元数据 ✅ |
| 执行时长 | 大文件需长时间任务 ❌ | 单次请求秒级返回 ✅ |
| 上传能力 | 必需 ❌ | **完全不需要** ✅ |

## 快速开始

### 1. 准备环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `YUN139_AUTH` | ✅ | 登录移动云盘后的鉴权串（**用 Secret 存储**） |
| `YUN139_HOST` | ✅ | 个人云域名，如 `https://personal-kd-njs.yun.139.com` |
| `YUN139_ACCOUNT` |  | 账号（手机号），部分接口需要 |
| `YUN139_KIND` |  | 盘类型：`personal`（默认）/ `family` / `group` |
| `YUN139_CLOUD_ID` |  | 家庭云 / 群组 ID（非 personal 时必填） |
| `YUN139_ROOT_ID` |  | 根目录 ID，留空表示用根目录 |
| `VIRTUALIZE_CAS` |  | 是否把 `.cas` 显示成真实视频名，默认 `true` |
| `AUTO_CLEANUP` |  | 播放后自动清理临时副本，默认 `true` |
| `ALLOW_EXT` |  | 允许播放的扩展名，逗号分隔 |

### 2. 本地跑起来

```bash
pnpm install
cp .dev.vars.example .dev.vars   # 填入你的账号信息
pnpm dev                          # 默认 http://127.0.0.1:8787
```

### 3. 部署到 Cloudflare

```bash
# 登录 CF
npx wrangler login

# 设置敏感变量（不会写进文件，安全）
npx wrangler secret put YUN139_AUTH
npx wrangler secret put YUN139_ACCOUNT   # 如需要

# 非敏感变量在 wrangler.toml 的 [vars] 里改好，然后部署
pnpm deploy
```

部署完会给你一个 `https://139openlist.<你的子域>.workers.dev` 地址。

### 4. 挂到网易爆米花

在爆米花的媒体库设置里选 **WebDAV**，填写：

| 字段 | 值 |
|---|---|
| 地址 | `https://139openlist.<你的子域>.workers.dev/dav` |
| 用户名 | 任意（如 `139`） |
| 密码 | 任意（如 `139`） |

> 当前版本不校验 WebDAV 账号密码，**请务必给 Worker 绑定自定义域名，
> 或改用 Cloudflare Access 做访问控制**，避免地址泄露后被人白嫖流量。

## 接口一览

| 路径 | 用途 |
|---|---|
| `/` | 状态页，含配置提示 |
| `/dav` | **WebDAV，推荐给播放器用** |
| `/strm` | 以 `.strm` 形式浏览可播文件 |
| `/play/<路径>` | 直接播放，自动 302 到真实视频直链 |
| `/api/health` | 健康检查 |

### 关于 `/strm`

给不支持 WebDAV、只认 `.strm` 的播放器用。
访问 `/strm/剧集目录` 会列出可播内容；访问 `/strm/剧集目录/某剧.mp4.strm`
会返回一行内容——指向本服务的播放地址。

## 设计上的几个取舍

**为什么是只读？**
本项目定位单一：解决"CAS 播不了"。写入、搬运、转存都涉及长时间上传，
在 Serverless 上是逆风局，不如不做，把这一件事做扎实。

**临时副本怎么清理的？**
Workers 没法可靠跑后台定时任务，所以用了双保险：

1. 播放后挂一个延时删除（借助 `waitUntil` 延长生命周期）
2. **惰性清理**——每次播放前顺手清掉超过 30 分钟的临时副本

即使两者都失效，临时文件也都在固定的 `TEMP/` 目录下且有 `TEMP_139OL_` 前缀，
手动清理很方便。

**`.cas` 为什么要"伪装"成真实文件名？**
因为播放器扫描媒体库时是按扩展名识别视频的。
展示 `.cas` 它直接跳过，展示 `movie.mp4` 它才会去点播——
点播时我们再在后台悄悄还原，播放器全程无感。


## 排查问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 提示"缺少 YUN139_AUTH" | Secret 没设 | `npx wrangler secret put YUN139_AUTH` |
| "秒传未命中" | 云端没有该文件内容 | 确认该 `.cas` 对应的真实文件还在云盘上 |
| "缺少 SHA256" | `.cas` 是旧工具生成的 | 用新版工具重新生成占位文件 |
| 播放器扫不到视频 | 扩展名不在白名单 | 调整 `ALLOW_EXT` |
| 目录能列出但播放 500 | 鉴权串过期 | 重新登录移动云盘，更新 `YUN139_AUTH` |
| 播放几秒后卡住 | 直链需带 Referer | 本项目已自动携带，若仍有问题请提 Issue |
